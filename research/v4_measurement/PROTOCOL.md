### Authority binding

This document is governed by the v4 authority-binding contract. Before any compatibility chat, the compatibility plan, full plan, and conditional GO must bind the exact frozen acceptance-matrix hash, authority-contract hash, external source-manifest hash, tag-blob comparison hash, completed eight-card audit hash, and pre-GO read-only runtime-identity hash. V4 is a new finite synthetic study. It does not retry, repair, trim, score, or
reuse the v3 population. The v3 operational failure is design history only:
v3 contributes zero cases, traces, rates, scores, or result claims.

The main panel contains exactly eight new, outcome-unseen synthetic cases. It
has one finance and one general future-information case, one finance and one
general current-anchor case, an original and a later restatement case, and a
not-yet-listed and a delisted survivorship case. Each case runs in unrestricted
and enforced retrieval modes, with two pinned models and two repetitions:
`8 x 2 x 2 x 2 = 64` primary trajectories. Repetitions are repeated traces,
not independent cases or population draws.

Before the main panel, the same production tool request and transcript shape is
used for exactly one excluded compatibility trace per model against the distinct
`compat-lantern-2022-08-schema` fixture. It is not one of the eight panel cases,
and cannot enter the projection. Each trace has two
chat requests, for four chats in total. The main 64 trajectories, and their
128 chats, run only if both compatibility traces are complete and valid. A
compatibility failure ends the campaign unsealed. It does not authorize a
resume, row replacement, parser relaxation, partial analysis, or retry.

Every claimed trajectory is journaled and fsynced before its first chat; its
terminal record is likewise fsynced. Raw first and final responses are written
before their native Ollama 0.33.2 envelopes are validated. Compatibility is
sealed as its own manifest before the main directory is created. The runner
uses only `http://127.0.0.1:11434`, reads `/api/version` and `/api/tags` before
compatibility, between phases, and after the main panel, and records those raw
identity responses. Analysis byte-replays requests, responses, and tool results.
Self-custody evidence supports internal consistency and byte replay; it detects
missing, partial, malformed, or inconsistent artifacts, including re-signed
artifacts without corresponding authority. It provides no independent
raw-response provenance and cannot detect a coherent rewrite of every locally
held artifact.

The first tool call accepts exactly one required nonempty `query` string and an
optional `date` string. When present, `date` must byte-for-byte equal the case
`as_of` value in `YYYY-MM-DD` form. Unknown keys, missing `query`, empty query,
wrong JSON scalar types, aliases, duplicate keys, and a date that differs from
the case cutoff are invalid. The optional date is an interface-compatibility
field only: retrieval and scoring use the case `as_of`, never the tool-call
date value.

The main estimand is the descriptive finite-panel difference `unrestricted
TCLR - enforced TCLR`, reported per model and pooled. TCLR is the share of
first-tool interactions whose returned record has a publication date after the
case cutoff. Query, restatement, and survivorship markers are separate
diagnostics. The study makes no significance, population, answer-quality,
live-web, model-ranking, or external-authenticity claim.

Each source-audit entry must contain an `ACCEPT` decision, a case-specific
nonempty reason, and its own strict UTC timestamp. The completed audit binds
the exact external source manifest, tag-blob comparison, annotated v4 tag
object, peeled commit, registry tagged-blob OID/SHA-256, and every case-card
tagged-blob OID/SHA-256. The pre-GO, read-only runtime identity binds that same
manifest, comparison, tag object, peeled commit, exact raw version/tags hashes,
server `0.33.2`, and the two approved model names/digests. The runner must
reject an incomplete audit or any mismatched binding. The source-audit UI creates
one external packet containing M, X, the review worksheet, and a receipt from
the clean detached annotated-tag checkout. Materialization, the runner, and
semantic replay independently derive M and all five no-overlap dimension sets in
X from exact v3/v4 annotated-tag blobs. They reject any M/X byte mismatch before
evidence output or transport; a cached projection or current-worktree
interpretation is not authority.

The runner accepts C/F/G/A/I/M/X only as external regular files and creates an
absent external evidence root through the shared reparse-safe admission path.
Repository-local files, symlink components, and Windows junction components are
rejected before output or transport. Native HTTP responses are streamed under a
1,048,576-byte per-response limit and an 8,388,608-byte campaign limit. An
over-limit response is a `resource` failure; only a bounded 4,096-byte received
prefix may be retained in replayable failure evidence.

No model call is allowed until a new canonical conditional GO binds the frozen
release, external source manifest, acceptance matrix, plans, case registry, completed Lester source
audit, no-overlap comparison projection, runtime identity, and approved model
digests. Before the first compatibility chat, the runner must require
`compatibility_plan.acceptance_matrix_sha256 ==
full_plan.acceptance_matrix_sha256 ==
conditional_go.acceptance_matrix_sha256 == SHA256(ACCEPTANCE_MATRIX.md)`.
That GO authorizes one conditional campaign only; it does not authorize
outreach, endorsement-code transmission, arXiv upload, or submission.
