# Lessons

## Derive schema counts from the literal ordered tuple

The cost/A8 architecture and final plan review repeated an inherited A8 check count even though the normative literal list had a different length. For every exact receipt schema, mechanically require declared count, literal length, unique-name count, and emitted-source tuple length to agree. For successor insertions, apply the operation to the predecessor tuple and compare the complete ordered result. Each review stage recomputes this from the frozen authority instead of copying a prior count.

## This task has no market-session dependency

The user clarified that the market-hours question was a mix-up. This task concerns a local LLM evaluation for a research paper. Do not import broker paper-trading schedules or market-open gates into its execution plan.

## Keep assurance work subordinate to the product acceptance matrix

The user corrected a process that was accumulating auxiliary assurance work without moving the v5 product toward its acceptance matrix. Iterate the smallest existing harness in an ordinary scratch workspace first, then freeze formal evidence only after the product path is working. Preserve failed assurance artifacts as history, but do not let their revision chain replace the release path.

## Scrub loader overrides for every pinned-interpreter probe

The v5 release candidate correctly scrubbed loader and Python path overrides for pinned-producer work, but its resource-admission probe bypassed that helper. On Linux Python 3.12, the pinned 3.12.10 executable inherited the candidate 3.12.14 `LD_LIBRARY_PATH` and failed before the paper tests. Route identity probes and production work through the same scrubbed subprocess helper, and test the admission call itself under polluted `LD_LIBRARY_PATH`, `PYTHONHOME`, and `PYTHONPATH`.

## Revalidate host dependency pins immediately before release

The v5 controller's PowerShell hash was correct when designed, but Windows replaced the signed binary on the morning of release. Offline controller tests mocked dependency admission, so the stale pin would have failed only at process preflight. Run the real read-only dependency identity check before tag creation and keep a Windows-only test that compares the current capture host with every pinned interpreter, package, helper, and executable identity.

## Exercise generated code in its exact namespace

The H18 compatibility checker compiled successfully but its selected generated module failed before the first row because the restricted builtins intentionally omitted `__import__` while the generated AST still contained a future import. For compile-plus-exec paths, inspect the generated AST and compiler flags against the exact globals and builtins, reject unavailable imports mechanically, and exercise the actual restricted namespace at the first authorized gate. Preserve the failed event and require a complete corrected event; containing-file compilation alone is preparation evidence.

## Derive diagnostic expectations from the frozen contract

The next H18 checker reached all 25 cases but failed six because its expected strings guessed English grammar instead of using the earlier Addendum03 contract. Freeze literal normative templates and a separately owned complete row oracle before examining the new event. Compare both the checker's expected fields and the observed fields with that oracle, including fixed labels and call counts. A failed attempt remains failed even when it exposes an oracle bug.

## Verify the actual materializer-to-consumer boundary

The v2 audit found a six-file materializer output while the runner required a seventh runtime identity file; a runner fixture manually supplied the missing file. Successor QA must pass actual materializer output directly to the production offline preflight, and must reject semantic-equivalent runtime JSON when its raw bytes differ from the receipt.

The historical controller gate missed path spelling, PowerShell argument delivery, process birth identity, and restoration retry publication. Review and QA must exercise the actual fixed helper argv and detached worktree, reject reused or inaccessible process identities without a stop signal, and fault-inject each restoration boundary before canonical publication. A passing simulated lifecycle does not replace the separately gated single operational capture.

Receipt fields are claims to verify. The runtime and schedule tests must independently hash actual member bytes, bind them to the receipt, and check schedule semantics against the frozen plan. Keep final PENDING validation separate from GO, and do not infer campaign execution qualification from identity-only or offline preparation evidence.

## Compare completion facts separately from qualification

The Matrix11 architecture gate approved contradictory expectations for otherwise equivalent fatal-event observations. Equivalent completion facts must produce equivalent completion status. The37-case detector rejects the original ledger05 and passes corrected ledger06; keep that mechanical proof alongside the production-frontier tests. ## Retain the complete outer command result

QA03's launcher printed only `exec_command`'s output string and discarded the session identifier at a 30-second observation yield. The child passed, but the outer exit could not be recovered. Store and render the entire result object; if it returns a session, poll that same session with `write_stdin` until an explicit terminal exit is observed. A receipt, empty stderr, or absent PID cannot supply an unobserved exit. The separately approved QA04 capture closed this gap without changing the candidate or reusing QA03 evidence.

Reset04's canonical detector passed, but an ad hoc QA wrapper asserted that stderr must be empty even though `unittest -v` writes its normal report there. Validate the strict child exit and the expected success transcript from the actual stream; preserve raw bytes and any later wrapper failure separately. The approved QA02 reconciliation checked the existing one-test transcript without rerunning the candidate. Architecture02 Prep01 passed CODE and QA because its sub-warmup test mutated consumer facts while its actual native-producer test exercised a different state. ## Admit exact CLI argv before consuming a unique gate

Reset04 attempt 1 had three approved, frozen source files, but root manually invoked the source-only detector without its required `--output` option. Argparse exited before the detector body, so no JSON receipt existed and the unique invocation could not be retried. Before any unique or one-shot receipt-producing CLI, statically derive required options from the frozen source or an independently frozen schema and admit the exact literal argv, cwd, script identity, option order/multiplicity, output path, and create-only output absence. Execute only the retained admitted argv; do not reconstruct it manually. Preserve malformed argv as RED. `prove_matrix11_reset05_controller03_cli_admission_01.py` demonstrates the original omission as RED and the intended `--output .\source03-attempt-01-static.json` argv as GREEN without launching the detector.

## Exercise the exact HTTP request serializer before a one-shot capture

The v3 identity controller's fake loopback responder accepted the request without
inspecting its headers. Python's `HTTPConnection.putrequest` supplied a default
`Host` header, then the controller supplied a second explicit header; the normal
Ollama server rejected the capture with HTTP 400 before any process mutation. A
transport gate must use a disposable raw socket that counts the exact serialized
headers, retain the frozen predecessor request as RED, and require the successor
to emit exactly one explicit host header before a capture is authorized.
