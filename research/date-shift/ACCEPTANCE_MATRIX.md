# Date-shift frozen acceptance matrix

The implementation candidate is reviewed against this unchanged matrix before any model outcome is requested.

| Gate | Pass condition |
| --- | --- |
| Cohort integrity | Exactly 60 candidate rows, exactly 54 mechanically proposed rows, and exactly six retained exclusions; author decisions retain every rejection and no substitutions are possible. |
| Upstream provenance | Every row binds the pinned ExAnte Wikipedia source frame; no ExAnte label, response, or reported score is reused. |
| Source integrity | Every admitted item has immutable pre/post revision identities, verified timestamps and full-content hashes, unique non-crossing anchors, disjoint normalized aliases, and a Unicode-safe post excerpt no larger than 4,096 UTF-8 bytes. |
| Honest curation | No file or manuscript calls the AI-assisted source mappings human validated; before execution every proposed row has a timestamped ACCEPT/REJECT decision, nonempty reason, and bindings to both source revisions. |
| Treatment isolation | For every item/model block, the two model-visible request packets become byte-identical when only `presented_document_date` is normalized. |
| Prompt hygiene | No condition name, oldid, URL, actual revision timestamp, source-route marker, or answer rubric outside the supplied document content is model-visible. |
| Audit scaffold boundary | Tracked proposed artifacts cannot be passed to a model runner. A create-only descriptor generated after all source/documentation changes and before the single scaffold commit binds the expected remote tag, source closure, and governed text. A clean detached checkout at the pushed annotated scaffold tag recomputes that descriptor and validates Git, committed blobs, and LF-governed text before runtime capture, sealing, execution, analysis, or qualitative export. |
| Sealed external bundle | A new, atomically renamed external bundle binds the complete personal audit, runtime preflight, audited frame/items, execution contract, schedule, static plan, and a final manifest. Incomplete or existing bundle directories are inadmissible. |
| Runtime identity | Both declared model names and full API manifest digests, Ollama CLI/API evidence, actual Windows CIM video-adapter/driver evidence, OS, CPU/RAM, Python version, and context setting are frozen before calibration. Additional installed models are allowed. |
| Calibration | One ordered strict-JSON calibration claim, terminal, and loaded-backend `ollama ps` evidence succeeds for each declared model before its first scientific claim. Missing backend evidence is a failure, never a placeholder. |
| Schedule | Exactly `N x 2 x 2` unique trajectories cover every author-accepted item, model, and primary condition once at the frozen seed and explicit decoding configuration, including `think:false`. |
| Durable execution | A new run directory begins with a bound v3 header. Every request has a fsynced claim before network I/O and exactly one terminal outcome; no overwrite, hidden retry, replacement, resume, or invented result is possible. Any unresolved claim is permanently `UNKNOWN_AFTER_CLAIM`. |
| Strict scoring | Answer class, citation compliance, and joint outcome remain separate; malformed JSON and transport failures are invalid outputs; `post_answer_exact` is answer-only primary and `grounded_post_exact` is a separately reported joint scalar. |
| Primary analysis | Replay accounts for every planned cell and separately derives complete-valid paired and all-planned-cell ITT forward, reverse, net, and marginal truthful-leakage metrics, with fixed denominators, model-by-arm invalid rates, and fixed-seed 10,000-resample topic-cluster intervals. |
| Qualitative audit | The separate treatment-label-blinded qualitative export omits identifiers, labels, scores, and citation metadata, aggressively redacts dates and temporal/eligibility clauses, and cannot change formal outcomes. It is not claimed to be semantically treatment blind. |
| Claim discipline | Generated prose is finite-set and model-build-specific and remains neutral for positive, null, or negative outcomes. |
| Cross-version quality | Full tests pass on Python 3.10, 3.11, and 3.12; pinned Ruff, compile, and diff checks pass. |
| Reproducibility | A clean checkout regenerates analysis tables, the readable PDF, and the arXiv source archive from the frozen tracked inputs and retained journal. |
| Paper completeness | The PDF contains results, methods, related work, limitations, attribution, and AI-assistance disclosure with no placeholder or blocked-scaffold language. |
| Review depth | Ten distinct review reports are complete, consolidated into at most three non-clean remediation cycles, and the final unchanged candidate passes reviewer and QA gates. |
| Outreach boundary | Only an unsent outreach draft exists; no researcher contact, endorsement request, account action, upload, or public submission occurs. |
